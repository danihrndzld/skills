# Table of specifications

Numbers in brackets refer to [references.md](references.md).

## What it is and what it's for

A table of specifications (also called a test blueprint) is a grid that crosses learning objectives with cognitive levels and gives each cell a number of items and points. Fives and DiDonato-Barnes [18] present it as the tool that organizes the decisions made while building a classroom exam and that improves the validity of the conclusions the instructor draws from the grades. Only the abstract of [18] was read; its detailed steps were not.

Guideline 1 of Haladyna, Downing and Rodriguez [1] asks the same from the item side. Each item should reflect specific content and a single mental behavior, as the test specifications require. The NBME guide [2] warns that if the items don't represent the domain well, the results can be biased and can't be used to estimate achievement in that domain.

## How to build it

1. **List the objectives** the exam covers, each with the verb from Krathwohl [9] that fits it (see [cognitive-level.md](cognitive-level.md)). Take them from the syllabus and the material the exam covers, not from memory.
2. **Give each objective a weight** based on the class time it received and its importance in the syllabus.
3. **Choose the format by level.** Remember and understand fit multiple choice or matching. Apply and analyze fit multiple choice with a scenario or short answer. Create fits a practical task.
4. **Spread the points** across cells and check that each row adds up to the weight from step 2.
5. **Write the items** and tag each one with its cell.
6. **Compare** the table with the finished exam at the end, looking for empty cells, cells with more items than planned, and objectives that don't appear.

## Example

An example blueprint for a 10-point introductory statistics exam:

| Objective | Remember / understand | Apply / analyze | Create | Points |
|---|---|---|---|---|
| Describe a data set with measures of center and spread | 4 MC (1.0) | 2 short answers (2.0) | | 3.0 |
| Read a chart and spot misleading scales | 2 MC (0.5) | 2 MC with a chart (0.5) + 1 short answer (1.0) | | 2.0 |
| Compute a probability from a two-way table | 2 MC (0.5) | 1 computation (1.0) | | 1.5 |
| Match sampling methods to their definitions | Matching, 4 premises (1.0) | | | 1.0 |
| Design and run a small survey analysis | | | Practical task (2.5) | 2.5 |
| **Total** | **3.0** | **4.5** | **2.5** | **10.0** |

MC = multiple choice worth 0.25 points. The numbers show one way to spread points, not a recommendation. The weight of each row comes from step 2.

## Use with parallel versions

The table is what keeps parallel versions equivalent (see [parallel-versions.md](parallel-versions.md)). Each version has to fill the same cells with the same number of items and the same points. If a clone in version 2 drops from "apply" to "remember" because the scenario lost a fact, version 2 no longer measures the same thing.

- **Do:** add a column to the answer key document with each item's cell in every version.
- **Do:** check the "Remember / understand" column. If it holds more than half the points and the syllabus objectives say "apply" or "analyze", the exam doesn't measure what the course promises.
- **Don't:** write the items first and build the table afterwards to justify them. Build the table before writing the first item.
